# Beztack: análisis de mercado de SaaS starters (noviembre 2026)

Alcance: competidores pagos y gratuitos de Beztack ([repo](https://github.com/V473r10/beztack), [sitio](https://www.beztack.com/)), comparación, debilidades, oportunidades e ideas. Fuentes consultadas entre el 10 y el 11 de noviembre de 2026. Muchas comparativas del sector las escriben vendedores de otros kits (MakerKit, supastarter, TurboStarter); se marcan como tales cuando son la fuente. El propio [Top Boilerplates advierte](https://dev.to/topboilerplates/what-we-learned-reviewing-162-saas-boilerplates-the-numbers-and-the-red-flags-4lg8) que casi toda la literatura comparativa la escribe alguien que vende un kit. Contenido parafraseado para cumplir restricciones de licencia.

Datos de estrellas y último push de GitHub obtenidos de la API pública de GitHub el 11/11/2026.

## 2. Dónde Beztack es más débil (sin anestesia)

1. **La licencia AGPL-3.0 es probablemente el mayor freno.** El repo figura como AGPL-3.0 en la API de GitHub. AGPL obliga a ofrecer el código fuente modificado a quienes usan el software por red, que es exactamente cómo funciona un SaaS ([opensourcealternatives.to](https://www.opensourcealternatives.to/blog/open-source-license-guide); [FOSSA](https://fossa.com/blog/open-source-software-licenses-101-agpl-license/)). Hay asesores legales que la llaman directamente la licencia "tóxica" para startups SaaS y la revisan en due diligence de inversores ([Promise Legal](https://blog.promise.legal/startup-central/open-source-license-compliance-for-startups/)). Todos los OSS que compiten (T3, Open SaaS, nextjs/saas-starter, ixartz, Better-T-Stack) son MIT, y BoxyHQ es Apache-2.0. Un fundador que lee "AGPL" en un _starter_ para su producto cerrado se va. Además el CLI en npm declara MIT, lo que genera confusión.

2. **Mercado dominado por Next.js; Beztack es Vite SPA + Nitro.** Next.js sigue con 60–70% de uso aunque baja la satisfacción ([Bitdoze](https://www.bitdoze.com/astro-vs-nextjs-vs-tanstack-start-which-wins-2026/)). Los compradores buscan "Next.js SaaS boilerplate" y todas las comparativas se ordenan por ese término ([MakerKit](https://makerkit.dev/blog/saas/best-nextjs-saas-boilerplate); [TurboStarter](https://www.turbostarter.dev/blog/best-nextjs-saas-boilerplate-2026)). La alternativa que crece es **TanStack Start** (1.0 estable en 2026, [tech-insider](https://tech-insider.org/tanstack-start-1-0-stable-release-2026/)), y MakerKit y supastarter ya venden kits para TanStack Start ([MakerKit](https://makerkit.dev/blog/changelog/introducing-tanstack-start-kit); [supastarter](https://supastarter.dev/tanstack-start-saas-boilerplate)). Una SPA pura sin SSR para la app no es un problema técnico para dashboards, pero Beztack no ocupa ni la categoría dominante (Next.js) ni la que sube (TanStack Start). Tiene que explicar por qué SPA + API separada, y hoy no lo hace.

3. **Cero tracción visible.** 0 estrellas, 0 forks, sin descripción ni topics en GitHub (API GitHub, 11/11/2026). Open SaaS tiene 16k, T3 29k, Better-T-Stack 5,9k. MkSaaS muestra 780+ clientes y Pegasus 1.913 usuarios en su portada ([mksaas.com](https://mksaas.com/); [Pegasus](https://www.saaspegasus.com/pricing/)). Sin prueba social, nadie entra al embudo.

4. **Mensaje inconsistente entre README, sitio y código.** El README describe Polar como integración de pagos, no menciona Mercado Pago y dice Next.js 15 en docs. El sitio ya presenta "Template Sync" como característica existente mientras sigue en evaluación (Copier, Cruft, Copybara, subtree) ([beztack.com](https://www.beztack.com/)). Top Boilerplates marca justamente "páginas del vendor que se contradicen" como señal de alerta para compradores ([dev.to](https://dev.to/topboilerplates/what-we-learned-reviewing-162-saas-boilerplates-the-numbers-and-the-red-flags-4lg8)).

5. **Sin demo en vivo.** MkSaaS tiene demo pública ([mksaas.com](https://mksaas.com/)), Pegasus ofrece "Try a Demo" ([pricing](https://www.saaspegasus.com/pricing/)), MakerKit recomienda evaluar el kit mirando la demo en móvil y dark mode ([MakerKit](https://makerkit.dev/blog/saas/best-nextjs-saas-boilerplate)). Beztack solo muestra una landing con logos de herramientas.

6. **Marca y posicionamiento genéricos.** "You want to ship. You need this." y "production-ready monorepo starter" es lo que dicen todos. El sitio enumera herramientas (Vite, nuqs, T3 Env) en lugar del resultado para el comprador. El diferenciador real (billing profundo con Mercado Pago, sync) aparece enterrado.

7. **Features de producto que el mercado da por sentados y faltan o están "coming soon".** Magic link, passkeys, OAuth y API keys figuran como "Coming Soon" en el sitio ([beztack.com](https://www.beztack.com/)); MakerKit ya trae passkeys ([MakerKit](https://makerkit.dev/blog/saas/best-nextjs-saas-boilerplate)). No hay evidencia de: landing/marketing site reutilizable para el producto del comprador, blog, i18n, tests E2E, admin panel general (más allá del de billing), Stripe. MkSaaS empaqueta landing, pricing, blog, newsletter, i18n y SEO por $129 ([mksaas.com](https://mksaas.com/)).

8. **Sin Stripe.** Stripe está en 40 de los 81 kits SaaS del directorio de Top Boilerplates ([dev.to](https://dev.to/topboilerplates/what-we-learned-reviewing-162-saas-boilerplates-the-numbers-and-the-red-flags-4lg8)). Un comprador fuera de LatAm que no quiere un merchant of record no tiene opción.

9. **Docs y comunidad.** No hay Discord, changelog público con versiones ni guía de "por qué esta arquitectura". MakerKit usa el changelog fechado y la versión de framework declarada como criterio número uno de compra, y por esa razón dejó de recomendar ShipFast ([MakerKit](https://makerkit.dev/blog/saas/best-nextjs-saas-boilerplate)).

10. **Riesgo de un solo mantenedor.** Top Boilerplates lo lista como señal de riesgo (no descalificante) que el comprador debe poder asumir ([dev.to](https://dev.to/topboilerplates/what-we-learned-reviewing-162-saas-boilerplates-the-numbers-and-the-red-flags-4lg8)). Sin historial público largo, Beztack no puede compensarlo todavía; MakerKit aplica ese mismo argumento a Achromatic.

11. **Amplitud de stack que suma superficie sin vender.** OCR y Bedrock son nichos; Nx en lugar de Turborepo va contra lo que usan casi todos los competidores (MakerKit, TurboStarter, Midday v1, Better-T-Stack). No es un error, pero cada elección poco común exige una explicación en la doc.

## 3. Dónde Beztack es (o puede ser) más fuerte

### 3.1 Mercado Pago y LatAm: hueco casi vacío

- En las búsquedas de 2026 no apareció ningún starter SaaS conocido con Mercado Pago integrado. Los únicos resultados son librerías sueltas, como una implementación de "suscripciones prepagas" para Laravel ([GitHub](https://github.com/javoscript/laravel-mercadopago-prepaid-subscriptions)). Los listados de proveedores de los kits líderes no lo incluyen: supastarter trae Stripe, Lemon Squeezy, Polar, Creem y Dodo ([supastarter](https://supastarter.dev/supastarter-vs-makerkit)), MkSaaS trae Stripe, Creem y Waffo ([mksaas.com](https://mksaas.com/)), y la calculadora de comisiones de supastarter compara seis proveedores sin Mercado Pago ([supastarter](https://supastarter.dev/tools/payment-fee-calculator)).
- La API de suscripciones de Mercado Pago (`preapproval`, `preapproval_plan`) es básica: el prorrateo que documenta solo cubre suscripciones que arrancan en un día distinto a la fecha de facturación ([MP docs](https://www.mercadopago.com.co/developers/es/docs/subscriptions/integration-customization/payment-methods/proportional-amount)). Todo lo que Beztack ya tiene (ledger de cambios pendientes, preview de prorrateo, cambio de cadencia, retry de cambios fallidos) es lógica que el dev tendría que escribir. Eso es exactamente el tipo de trabajo que, según MakerKit, un agente no resuelve bien porque es caro de revertir ([MakerKit](https://makerkit.dev/blog/saas/best-nextjs-saas-boilerplate)).
- Combinación Polar (MoR global, impuestos en 100+ mercados, [Polar](https://polar.sh/features/merchant-of-record)) + Mercado Pago (cobro local en moneda local) cubre al fundador LatAm que vende a EE.UU./UE y a su país. Ningún competidor ofrece esa pareja.

### 3.2 Template sync: el dolor más citado y peor resuelto

- supastarter admite en su doc que cada cambio propio hace más difícil actualizar, porque en la práctica se hace rebase sobre su código ([docs](https://supastarter.dev/docs/nextjs/codebase/update)). MakerKit propone `git pull` + merge ([docs](https://makerkit.dev/docs/next-supabase-turbo/installation/updating-codebase)). Open SaaS tituló su guía "How (Not) to Update" ([docs](https://docs.opensaas.sh/guides/updating-opensaas/)).
- El caso más claro es el incidente de Open SaaS de 2025: la falla en `updateCurrentUser` afectaba a toda app creada antes del 14/02/2025 y cada una tuvo que aplicar el fix a mano ([incident report](https://docs.opensaas.sh/blog/2025-02-26-incident-report-vulnerability-in-open-saas/)). Un sync con PRs habría entregado el parche a todos los derivados.
- Solo Pegasus (Django) lo resolvió comercialmente con PRs automáticos y un skill de Claude Code que corre el upgrade ([docs](https://docs.saaspegasus.com/upgrading)). En el ecosistema TypeScript nadie lo tiene: es un diferenciador real si funciona.
- Herramientas base disponibles: Copier con merge de 3 vías ([docs](https://copier.readthedocs.io/en/stable/updating/)) y actions-template-sync para abrir PRs ([repo](https://github.com/AndreasAugustin/actions-template-sync)). Cruft está estancado desde dic. 2024 (API GitHub), así que no conviene apostar por él.

### 3.3 Docs orientadas a agentes

- Top Boilerplates encontró que pocos kits traen de verdad CLAUDE.md o AGENTS.md aunque muchos se venden como "AI-ready" ([dev.to](https://dev.to/topboilerplates/what-we-learned-reviewing-162-saas-boilerplates-the-numbers-and-the-red-flags-4lg8)). Beztack ya tiene AGENTS.md, glosario CONTEXT.md y ADRs, un nivel de "por qué" que la mayoría no documenta.
- MakerKit es el líder (MCP con 56 herramientas, [MakerKit](https://makerkit.dev/ai-saas-starter)) y Pegasus ya usa skills para upgrades. Beztack puede competir aquí si suma un MCP/skill específico (por ejemplo "agregar un plan", "migrar de proveedor de pagos", "aplicar template update").

### 3.4 Profundidad de billing

- La mayoría de kits cubren checkout + webhook + portal. Pegasus anuncia per-seat y usage-based ([Pegasus](https://www.saaspegasus.com/pricing/)); MakerKit, billing por cuenta. Ninguno de los revisados documenta públicamente un ledger de cambios de plan pendientes con retry administrable. Beztack tiene un caso fuerte para B2B que cobra en LatAm, siempre que lo muestre (demo + doc).

### 3.5 Arquitectura SPA + API separada como posicionamiento

- Hay fatiga con Next.js: devs reportan que el App Router y las directivas de cache "se sienten como un segundo trabajo" y que no saben dónde corre su código ([dev.to](https://dev.to/beyondit/nextjs-16-vs-tanstack-start-2026-performance-memory-leaks-migration-guide-1chg); [dev.to](https://dev.to/elvissautet/nextjs-finally-has-competition-2lg7)). Vite + API Nitro desplegable en cualquier runtime es un argumento a favor de "sin magia, sin lock-in a Vercel", y la API separada sirve también para mobile o clientes externos. Better-T-Stack valida la demanda: su configuración por defecto es TanStack Router + Hono, no Next.js ([issoh.co.jp](https://www.issoh.co.jp/tech/details/10225/)).

## 6. Opciones de precio y monetización

Referencias de mercado: la mediana de precio en el catálogo de BoilerplateHub es US$149 ([BoilerplateHub](https://boilerplatehub.com/detail/ShipFast)); el rango de kits Tailwind va de US$55 a US$349 ([BoilerplateHub](https://boilerplatehub.com/categories/Tailwind)). MakerKit estima que construir esto desde cero cuesta US$7.500–12.000 de tiempo de desarrollo frente a US$199–499 por un kit ([MakerKit](https://makerkit.dev/blog/tutorials/cost-saas-starter-kit)). El modelo dominante es pago único con updates de por vida (MakerKit, supastarter, MkSaaS); Pegasus es la excepción con 1 año de updates incluido ([Pegasus](https://www.saaspegasus.com/pricing/)).

| Opción                                                 | Cómo sería en Beztack                                                                                                                                                                                                        | Pros                                                                                                             | Contras                                                                                          |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **A. Open core**                                       | Core MIT gratis (auth, orgs, db, Polar básico). "Beztack Pro" pago único US$149–249: módulo de billing avanzado (ledger, prorrateo, cadencia, admin de retries), adapter Mercado Pago completo, plantillas de landing/emails | Modelo probado (MakerKit Lite → Pro, Pegasus OSS → Unlimited); el OSS trae estrellas y tráfico                   | Hay que separar repos o paquetes privados, lo que complica el template sync                      |
| **B. Dual license**                                    | Todo el código AGPL público; licencia comercial (US$99–199) para quien no quiera cumplir AGPL                                                                                                                                | Mantiene todo abierto; convierte la AGPL en un embudo de ventas                                                  | Mucha gente ni siquiera evalúa repos AGPL; hay que explicarlo muy bien                           |
| **C. Template sync como servicio (suscripción)**       | Kit gratis/MIT; GitHub App "Beztack Sync" que abre PRs de upgrade, avisos de seguridad y skill de resolución por US$10–20/mes o US$99/año                                                                                    | Ingreso recurrente atado al diferenciador real; se alinea con el costo de mantener; nadie lo vende en TypeScript | Hay que construir y operar un servicio; el comprador de starters está acostumbrado al pago único |
| **D. Pago único + updates por 1 año** (modelo Pegasus) | US$199 con un año de sync; renovación opcional US$79/año                                                                                                                                                                     | Financia el mantenimiento sin "lifetime" insostenible                                                            | Menos atractivo frente a "lifetime" de la competencia                                            |
| **E. Precio regional LatAm cobrado con Mercado Pago**  | Precio en ARS/UYU/MXN/BRL vía el propio módulo de pagos de Beztack; precio USD vía Polar                                                                                                                                     | Dogfooding: la compra es la demo del producto; poder adquisitivo local                                           | Más trabajo contable y fiscal (impuestos locales)                                                |
| **F. Servicios**                                       | Llamadas de consultoría (supastarter las vende, [Starter Story](https://www.starterstory.com/businesses/supastarter)), setup "done-for-you" de Mercado Pago, migraciones de Stripe → Mercado Pago/Polar                      | Ingreso inmediato con pocos usuarios; feedback directo                                                           | No escala; consume el tiempo del único mantenedor                                                |
| **G. Sponsors / GitHub Sponsors / afiliados**          | Sponsors de herramientas del stack (Polar, Better Auth); afiliados de proveedores de hosting/pagos                                                                                                                           | Bajo esfuerzo                                                                                                    | Ingresos chicos sin tracción previa                                                              |

**Recomendación:** 1) resolver la licencia ya (MIT para el core, o dual license explícita); 2) open core (A) con Pro de pago único en US$149–199, cobrado en USD vía Polar y en moneda local vía Mercado Pago (E); 3) cuando el template sync funcione, sumar la suscripción de sync (C) como upsell para quien quiere upgrades automáticos más allá de un año. Ofrecer servicios (F) desde el principio para financiar el trabajo y descubrir qué falta. Para dimensionar: supastarter llegó a ~US$10k/mes después de unos dos años ([Indie Hackers](https://www.indiehackers.com/post/i-quit-my-job-to-go-all-in-on-my-saas-starter-kit-c57844cd75)), y ShipFast, el caso extremo, lo logró apoyado en la audiencia previa de su autor ([webtribunal](https://webtribunal.net/shipfast-picks-and-shovels/)).
